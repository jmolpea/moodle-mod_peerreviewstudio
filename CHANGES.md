# Changelog

## 0.9.12 (2026-11-12)

Two defects found while running a full course as a test student.

### Fixed
- **Students and teachers could not see the activity at all.**
  `mod/peerreviewstudio:view` declared
  `clonepermissionsfrom => moodle/course:view`. When that key is present
  Moodle copies the permissions of the named capability and ignores the
  archetype defaults, and `moodle/course:view` is held by managers only.
  The key is removed, so new installs get the archetype defaults
  (student, teacher, editing teacher, manager). An upgrade step grants the
  capability to the student, teacher and editing-teacher archetype roles
  that have no permission set for it yet; roles an administrator already
  configured are left alone.
- **The activity name and description were shown twice** on the activity
  page. Moodle 4.x renders both in the standard activity header, so
  `view.php` no longer prints its own copy.

### Known issues, not addressed in this release
- When the AI answer cannot be parsed as `{"grade", "feedback"}` (for
  example, because the activity prompt asks for a table), the fallback
  review task fails and is retried without limit.
- The "0 / 2 target" indicator does not change after the learner submits
  both assigned reviews.

## 0.9.9 (2026-07-04)

Security, privacy, and configurability pass over the AI second review.

### Changed
- **AI prompts are now configured per activity, not site-wide**: the
  "grade the submission" and "assess the reviewer" prompts moved from
  the site plugin settings into the activity settings form (visible when
  AI review is enabled). Empty prompt fields fall back to the plugin
  defaults. The upgrade step migrates any customised site-wide prompts
  into existing activities so behaviour does not change silently.
- **Richer AI context**: besides the prompt, the AI now receives the
  activity name, the activity description/instructions shown to
  learners, the grading frame, and the full rubric, together with the
  submission (and, for reviewer assessment, the complete peer review).

### Security
- Learner-generated content (submission text, review comments) is sent
  to the AI wrapped in explicit untrusted-content markers, and the
  system prompt instructs the model to never follow instructions found
  inside it (prompt injection defence). Marker text smuggled into a
  submission is stripped before wrapping.
- Rubric labels, descriptions, and level labels are now escaped before
  being rendered in the review form (defence in depth against stored
  XSS via restored course content).

### Privacy
- The privacy provider now declares the external AI provider as an
  external location (`add_external_location_link`), documenting exactly
  which content is sent (activity context, submission text and file
  names, review answers and comments) and that no user names, emails,
  or other personal identifiers are ever included.
- Learners see a clear notice on the activity page when AI review is
  enabled, before they submit anything.

### Fixed
- All remaining moodle-cs (Codechecker) warnings: language string
  ordering in `lang/en` and `lang/es`, inline comment style in
  `lib.php` and the unit tests, and the backtick characters in the
  AI client's markdown-fence stripping regex.

## 0.9.8 (2026-07-03)

### Added
- **Manual queue repair for tutors**: a "Process assignment queue now"
  button on the tutor dashboard retries every pending queue entry
  immediately (instead of waiting up to 10 minutes for the scheduled
  task), and the per-row Requeue / Assign manually actions now also
  appear for submissions whose owner already finished reviewing
  (status "Reviewed") but which are still waiting for reviewers —
  previously that state hid the actions entirely.
- **Optional AI second review** (site-configurable, per-activity opt-in):
  - Site administration > Plugins > Activity modules > Peer Review
    Studio: choose a provider (OpenAI, Anthropic, Google Gemini, or
    DeepSeek), enter the API key, pick a model per provider, and
    customise the two grading prompts (one for grading submissions, one
    for assessing reviewers).
  - Per activity: an "Enable AI second review" checkbox plus a
    configurable AI grade weight (0-100%). The submission grade becomes
    peer average × (100 − weight)% + AI grade × weight%.
  - The AI also assesses the quality of each peer review (rubric
    consistency, specificity, tone); that quality score (0-100) scales
    the reviewer's participation grade.
  - Evaluations run as ad-hoc background tasks after each review is
    submitted, so learners never wait on an API call; grades refresh
    automatically when results arrive.
  - The author sees the AI grade and feedback in a dedicated panel
    (only when feedback is released), with a clear "generated by AI"
    disclaimer; the tutor dashboard shows the AI grade per row.
  - Online text is sent to the provider; attached files are described by
    name only. Backup/restore and the privacy provider cover the new
    fields (AI feedback is exported and deleted/anonymised with the rest
    of the user data).

## 0.9.7 (2026-07-03)

UI/UX and scalability pass.

### Changed
- **Learner submission UX**: after submitting, the workspace now shows a
  clear success banner (check icon, "your submission is stored", last
  submission date) with the submitted text/files preview, and the edit
  form is collapsed behind an "Edit my submission" disclosure instead of
  sitting fully expanded with a second "Submit my work" button. The form
  reopens automatically if an edit fails validation, and its submit
  button now reads "Update my submission" when editing.
- **Tutor dashboard scalability**: filtering (status + name/email search)
  and pagination now happen in SQL (25 rows per page with
  previous/next controls that preserve active filters). Previously every
  submission row was loaded and the expensive reviewer-eligibility scan
  ran for all of them on every page view — O(N²) queries that would not
  survive hundreds of submissions. Eligibility is now only computed for
  the rows on the current page, and the incident panel only scans
  submissions that can actually have incidents (pending queue or
  unassigned), capped at 20 rows.
- **Visual refresh**: success/notice states, focus rings, hover states,
  sticky table headers, zebra-free hover rows, horizontal scroll
  containers for wide tables (no more layout breakage on narrow
  screens), pagination controls, tabular numerals for metrics, subtle
  hero gradient, and `prefers-reduced-motion` support.

## 0.9.6 (2026-07-03)

### Fixed
- `peerreviewstudio_get_rubric_answers_by_review()` used `a.reviewid` as
  the first column of a `get_records_sql()` call; with more than one
  rubric answer per review, Moodle's DML collapses rows with duplicate
  first-column values and emits "Duplicate value found in column
  'reviewid'" debugging warnings. The query now selects the unique
  `a.id` first, so every rubric answer line is preserved.

## 0.9.5 (2026-07-03)

### Fixed
- **Critical**: `peerreviewstudio_get_eligible_reviewers_for_submission()`
  selected candidate submission rows without their `status` column, but
  `peerreviewstudio_evaluate_reviewer_candidate()` reads
  `$candidate->status` to decide eligibility. The undefined property
  coerced to `''`, which never matches the active-status whitelist, so
  **every candidate was rejected as `candidateinactive` regardless of
  their real state** — silently breaking automatic peer assignment for
  any activity with more than one submission (visible as "Warning:
  Undefined property: stdClass::$status" on screen, 0 eligible reviewers
  in the tutor dashboard, and submissions stuck in the pending queue
  forever). Fixed by adding `s.status` (and `s.timesubmitted`, also read
  downstream) to the query. Existing pending queue entries recover on
  their own once the scheduled task or another submission re-triggers
  queue processing. Added a regression test for the positive-eligibility
  path; the previous single eligibility test only checked a reciprocal-
  block case that happened to also return 0 candidates under the bug,
  which is why it went undetected.
- Added an upgrade step that re-grants `mod/peerreviewstudio:view`,
  `:submit`, `:review`, and `:viewownstatus` to the student archetype for
  any role that has no explicit capability override yet. Moodle only
  auto-applies a capability's archetype defaults the first time that
  capability is introduced; sites that installed an earlier build (where
  these capabilities were not yet granted to students by default) never
  retroactively received the corrected defaults, which is why "View the
  Peer Review Studio activity" could still show as manager-only even on
  an up-to-date plugin copy.

## 0.9.4 (2026-07-03)

### Fixed
- Fixed "Incorrect grade array index, must be user id! Grade ignored." on
  every submission/regrade. `peerreviewstudio_grade_user_update()` and the
  null-grade branch of `peerreviewstudio_update_grades()` built the grades
  array indexed by position (`[0 => $grade]`) instead of by user id
  (`[$userid => $grade]`), which `grade_update()` requires; the grade was
  silently dropped from the gradebook every time. Added a regression test
  that reads the grade back via `grade_get_grades()`.

### Added
- Spanish translation (`lang/es/peerreviewstudio.php`), matching every
  string key in `lang/en/`. Previously, on a Spanish-language site, all
  core Moodle chrome (availability, restrictions, common module settings)
  appeared in Spanish while every plugin-specific label (workflow,
  grading, rubric settings) fell back to English, since no translation
  existed.

### Notes
- If an activity does not appear on the course page for a student despite
  "Show on course page" and no restrictions, this is not something the
  plugin's code controls (it never touches `course_modules.visible`).
  Check the activity's availability dropdown for "Available but not shown
  on course page" (stealth) and purge caches
  (Site administration > Development > Purge caches).

## 0.9.3 (2026-07-03)

### Added
- New **Open / self-paced (always on)** workflow mode. Unlike Scheduled
  (date-driven) and Manual (tutor-driven), Open mode has no shared
  activity-wide phase at all: submissions are always accepted, and each
  learner moves through review and feedback on their own as soon as they
  submit and are matched with a reviewer. Designed for rolling,
  self-enrolment courses and OER material where there is no fixed calendar
  and no tutor available to flip phases by hand.
  - `peerreviewstudio_phase_allows_submissions()` / `_reviews()` always
    return `true` in Open mode; per-user access is already gated
    separately by whether the learner has an assignment.
  - `peerreviewstudio_phase_allows_feedback()` now optionally takes the
    submission it is being checked for; in Open mode feedback is released
    to that submission's author as soon as *that submission* reaches its
    reviews-received target (status `closed`), independent of any other
    participant's progress.
  - The date fields (open/close/review-due) are hidden and ignored in
    this mode, so leftover dates from a previous workflow mode cannot
    accidentally gate it.
  - The phase bar shows a single "Ongoing (self-paced)" indicator instead
    of a step sequence.

## 0.9.2 (2026-07-03)

Second aggressive review pass (directory-reviewer / security-audit lens).

### Fixed
- Files embedded in the activity description (intro) returned 404: the
  `pluginfile` callback only served `submission_files`. It now serves the
  `intro` file area too.
- Manually assigning a reviewer to a submission that had already received
  reviews reset its status to `assigned`, losing `partiallyreviewed` /
  `reviewed` / `closed` progress. Manual assignment now only advances
  pre-review states, matching auto-assignment.
- Learners whose own submission reached the reviews-received target
  (status `closed`) were silently excluded from the reviewer pool, starving
  late submissions of reviewers. `closed` is now an eligible candidate state,
  and completing a review no longer downgrades a `closed` submission.
- The review rubric preselected the first level of every criterion, so a
  reviewer could submit without consciously rating anything, and an
  unanswered criterion was silently dropped from the grade calculation.
  Each criterion now starts on a "Choose..." option and server-side
  validation requires a level that belongs to that criterion.
- Deleting an activity instance could leave orphaned assignment/queue rows
  when their submission row was missing; deletion now also clears both
  tables by activity id.

### Added
- `course_module_viewed` event on view.php and
  `course_module_instance_list_viewed` on index.php (standard logging
  expected by the Moodle Plugins Directory review).

## 0.9.1 (2026-07-02)

Hardening release after the pre-publication review.

### Fixed
- Fatal: illegal `void|false` return type in `peerreviewstudio_pluginfile()`
  prevented the plugin from being parsed/installed on PHP 8.1+.
- Fatal: the tutor dashboard renderer declared `stdClass` for the module
  context parameter and crashed for any user with reporting capabilities.
- Scheduled workflow mode now requires the close and review-due dates, so the
  review phase and feedback release always happen (previously the default
  configuration never left the submission phase).
- Editing the activity settings no longer recreates the rubric: criteria and
  level ids are preserved in place, so stored rubric answers survive setting
  changes. The rubric structure is locked once reviews exist.
- Editing a submission no longer requeues it and no longer stacks additional
  reviewers past the reviews-received target.
- Review grades are now proposed in submission-grade space and the submission
  grade is the average of received proposals — the rubric result now always
  drives the grade (previously it was ignored when the review component
  was 0, producing all-or-nothing grades).
- Gradebook item maximum now matches the configured component maximums.
- `pluginfile` access no longer honours cancelled reviewer assignments.
- Replaced the unverifiable `file_get_max_files()` call with a plugin
  constant (20 files per submission).

### Added
- Backup/restore now includes submission files and honours the "include user
  information" backup setting; view/index links are encoded and decoded.
- Privacy provider: userlist provider interface, file export, file deletion
  on delete/anonymise, and complete metadata declarations.
- Standard gradebook callbacks `peerreviewstudio_update_grades()` and
  `peerreviewstudio_get_user_grades()`.
- Scheduled task retrying pending reviewer-assignment queue entries every
  10 minutes.
- Automatic assignment now fills each submission up to the reviews-received
  target instead of assigning a single reviewer.
- Course `index.php` listing, activity icons (`pix/monologo.svg`,
  `pix/icon.svg`), and `FEATURE_MOD_PURPOSE` (assessment) support.
- Capability language strings, `modulename_help`, and other missing strings;
  default rubric content is now translatable (was hardcoded Spanish).
- Accessibility: phase bar exposes `aria-current="step"` and a list role;
  manual-assignment selector gained a screen-reader label.

### Changed
- English language file fully sorted; help texts rewritten to match the real
  grading and workflow behaviour.
- Tutor dashboard computes reviewer eligibility once per participant and
  derives the incident list from the same data (fewer queries per page load).
- README rewritten as user-facing documentation.
